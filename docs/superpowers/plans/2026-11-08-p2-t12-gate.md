## What is built
1. **Consistency rules 9 to 12 in the nightly job** (`app/os/consistency/facts.py`). The check reads what a student would be
   shown (the ProgrammeFacts port, so the display and labelled-year rules are the ones under test) for each programme of
   each open plan: 9 a value from a domain off the allow-list; 10 a high-stakes value below `verified`; 11 another intake
   shown without its year; 12 a value from a `suspect` domain. Codes name the rule and the field, never a value. Port
   functions `fact_students` / `fact_findings` in `ports/consistency.py`; the host job (`pai_os_bridge.consistency_run`) runs
   them after rules 1 to 8 and opens cases through the same case store. Migration `os_0033` widens the case rule check to
   1 to 12; the admin list names rules 9 to 12.
2. **R-69, the queue as the one spreadsheet** (`knowledge/review/export.py`, `GET /admin/review/export`): open items with a
   fact become rows of the Facts sheet (`fact_id` = `Q-<item>`, checker columns empty); the file imports back.
3. **Not-readable sources become collect items** (`ReviewQueue.sync_not_readable`, also in the admin sync): T4's open
   `os_not_readable` rows for a field with an intake year; collecting closes them.
4. **Scripted gate proofs** (`tests/os/gate/test_p2_gate.py`): spam page (item 4, with the real queue), not-readable source
   collected with evidence and approved by two more reviewers (item 5), spreadsheet round trip with the five deliberate errors
   and undo (item 10), rules 9 to 12 on a clean and a violating student (item 11), the R-69 round trip, and a manifest that names
   the existing proof for items 6, 8, 9 and 11 (rows 6.20, 6.25) and checks that it exists. Items 8 and 9 reuse T7's and T8's
   scripted tests.
5. **Spike 1 rerun harness per region** (`app/os/gate/spike1.py`, `scripts/os_spike1_rerun.py`): answer keys
   `tests/os/quality/<region>_answer_key.yaml`; `score` compares the facts held with the key (100% verified, 95% confirmed, a
   sample of 5 institutions); `plan` estimates a billed run against the US$20 cap; no live call, no model.
6. **`check_traceability.py --gate P2`** passes: every P2 R-ID is `built: true` with a tagged test.
7. **`docs/connect/handoff/p2-handoff.md`**, a draft marked "awaiting the owner's sign-off": what was built, the gate table with
   its status, every owner ruling, every open gap.

## Not in this task
The live Spike 1 run (the controller, inside the cap), the people lane (H2 to H7 sign-off rows, answer keys), and the owner's
sign-off. The handoff says so.
