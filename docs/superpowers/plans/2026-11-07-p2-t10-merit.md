Part one only. The freeze-exception PR for the Counsellor's merit answers (`CONNECT_MERIT_ANSWERS`) is a later, separate step.
Spec: P2 §4.10, P2-D26, P2-D27, row T10. Contracts: T1's `programme_facts.v1`, `merit_check.v1` (levels verified /

No migration: facts are Knowledge rows, so nothing new in the database.

## Decisions made here
- **Fact shapes** are checked in `knowledge/merit.py`; field names `merit_formula` and `closing_merit`, with a category
  suffix `_<slug>` when a formula or merit depends on a seat category. Both classes already exist (high-stakes).
  - `merit_formula` value: `{parts: [{name, marks_part, weight}], total}`; `marks_part` is the Vault fact key of the marks
    obtained (its total comes from the same pairs the eligibility code uses, `requests/limits.yaml` and document types).
  - `closing_merit` value: `{value, list_number|null, list_complete}`. `list_complete: false` needs `list_number`: it
    is "lowest on list N", never the closing merit (R-31). Bad shapes are refused at `check_fact_value`.
- **MeritCheck** computes with `eligibility.methods.weighted_aggregate` (P2-D26), scaled to the formula's total. Order of
  answers: formula missing or not `verified` -> `not_confirmed` (no aggregate, no formula value); else a mark missing
  -> `missing`; else `computed`. A mark held at evidence stated / shown / confirmed counts; the evidence is reported.
  There is no chance or prediction field anywhere.
- **Closing merits** are read for the three years before the intake (data: `merit.yaml`), each through the display rule:
  a value travels only at `verified`.
- **ProgrammeFacts** lists the playbook's programme fields plus every field Knowledge holds for the programme, read with
  `fallback_previous=True` so an earlier year's fact is labelled with its own intake (`other_intake`).
- **programme_list.v2**: coverage level computed from Knowledge (listed / researched / verified) because T2's registry
  is not on this branch; `region` is None until T2's column exists; `not_run_yet` = listed.
- **R-30 proof**: test over every playbook: a duration constant without a citation is `estimate: true`, and a step that uses an
  estimate is `estimated` in the compiler and in the plan view; the frontend label test is run too.

## Review fixes (I1, M1-M8)
- **I1.** `Playbook` refuses a constant that a step uses as duration, lead time or note placeholder and that is neither cited nor
  `estimate: true`. The audit test covers all three uses; negative tests build such a book. Every shipped duration constant was already
  `estimate: true`, so no playbook file changed.
- **M1.** A part held but unusable (above its total, or two different totals held) is `not_confirmed`; an absent part is `missing`.
  `marks_used` shows what the Vault holds. Overall status: any missing part -> `missing`, else any not_confirmed -> `not_confirmed`.
- **M2.** A fact whose term was never recorded gets the term `unrecorded` in `IntakeRef` fields (the frozen contract needs one);
  ProgrammeFacts then sets `other_intake` true. T8's backfill removes these.
- **M3.** The answer's `category` is set only when a category-specific formula was used; the general formula answers with none.
- **M4.** Empty-term rows are read with the port's exact filter `intake_term=""`.
- **M6.** The year floor is read from `IntakeRef`. **M7.** Reserved merit field prefixes are documented in `knowledge/merit.py`.
- **M8.** Coverage ignores rows with no value and lead-only/rejected/superseded/not-found statuses; two different totals for one mark are
  not guessed (`not_confirmed`).

## Notes for the freeze-exception PR (Counsellor merit answers)
- The Counsellor must read a part's reason from `parts[].status` (`missing` = ask the student; `not_confirmed` = a "which is right"
  question), not from the marks alone. A v2 contract could add an explicit reason field.
- **M5 (evidence of the aggregate).** The MeritCheck aggregate has no single evidence level. It shows as `computed` even
  when every mark is only `stated`. Evidence is tracked per mark in `marks_used`, as the weaker of the mark and its total.
  R-73 expects Part-I marks at `shown`. So the Counsellor-side merit answer must state the weakest evidence among the marks
  used, for example: "based on marks you told PAI; upload your result card to confirm." It must never present a
  stated-only aggregate as a firm number. No code change in MeritCheck now.
- The Counsellor must print the year of any `other_intake` fact and `unrecorded` terms as "term not recorded".
