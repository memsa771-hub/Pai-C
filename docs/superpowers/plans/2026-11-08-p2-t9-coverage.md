# P2-T9 plan: coverage API and screen, the R-35 reading, the intake `current` gate, the workload estimate (R-34, R-35, R-66)

Spec: P2 §4.9, row T9. Builds on T2 (`coverage_map`, `list_progresses`, registry) and T8 (`IntakeStore`, `slot_report`).
Branch `pc/p2-t9-coverage` from integration 409f7e9. No migration is needed: everything is computed from tables that exist.

## Decisions made here
- **One report per intake** (an `os_intakes` row = region, family, term, year). `GET /v1/os/admin/coverage?intake=<id>` returns:
  rows per institution type (denominator, listed/researched/verified, high-stakes verified / not confirmed / missing,
  not-readable), intake-level counts (suspect domains, open review items), the four gate readings, and the workload.
- **The expected fields are data** (`coverage/expected.yaml`): the verified-floor fields (R-35b: deadline, merit formula,
  eligibility threshold), per family with a `default`; required institution types (empty by default: then every type that
  has an official list in the region is read); checks per fact and the work-day assumptions of the estimate. The rollover
  slots of T8 (`os_fact_slots`) add the high-stakes keys the previous year had.
- **Gate (R-35):**
  - (a) every official list of the region/family: count published, confirmed, loaded = published (none over); no list at all is red;
  - (b) every institution of the family whose first-live intake is this one (`attrs.first_live` lists `<term>:<year>`): each
    programme x floor field is `verified`;
  - (c) every other high-stakes fact is `verified` or carries an official URL and quote ("not confirmed" with the link);
  - (d) every institution with no official online information is still `listed`.
  Green only if all four are green; each red lists its failing items (code, subject, detail).
- **`current` only through the gate (R-66):** `IntakeGate.pass_gate(intake_id)` reads the report and, only when green, calls
  `IntakeStore.set_state(id, "current", gate_passed_at=now)`. `POST /v1/os/admin/intakes/{id}/current` answers 409 with
  the failing items while red.
- **Workload (master §12):** registry size x high-stakes facts per institution x checks per fact, against the measured
  rows per hour (rows verified by review in the last N days / (worked days x hours per day)); hours is None when nothing
  is measured yet. It feeds the owner's checker decision.
- **Screen** `os-admin/coverage`: admin token typed per visit (as the support page); intake picker, gate cards red/green
  with failing items, table per institution type, workload.
