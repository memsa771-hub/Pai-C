# P2-T6 spreadsheets: plan (R-67, R-68, R-69, R-76)

Spec §4.6, P2-D16, P2-D16a, P2-D17, P2-D18; v4 rules in `docs/research/batches/README.md` (on `pc/p2-research-batches`).
Migration `os_0027_imports` (down_revision `os_0026`). New dependency `openpyxl`.

## Design
- Package `app/os/knowledge/sheets/`: `format.yaml` (columns, vocabularies, mappings), `legacy/*.yaml` (one Programmes
  layout per old batch), `reader.py` (xlsx/CSV -> canonical rows, legacy conversion), `plan.py` (pure: validate + status
  mapping per row; a dry run is exactly this), `importer.py`, `refetch.py`, `undo.py`, `importlog.py`, `template.py`.
- Canonical layouts: Institutions and Facts are the batch (v4) layouts; Programmes is the R-67 canonical one. Checker
  columns are the v4 ones (`checker1_result ... checker_note`); the name columns carry the reviewer ref (reviewer mode)
  or the AI check name (owner-accepted mode). Deviation from the column names in spec §4.6, which no batch uses.
- Modes: `owner_accepted` (P2-D16a; both checks must be the two AI checks; requires a decision ref; provenance
  `claude_check_1/2`, `accepted_by: owner`) and `reviewers` (checkers must have attested the batch, two different ids).
- Outcomes per row: accepted (verified/confirmed), unconfirmed, queued (import_dispute / collect / conflict item),
  rejected (reason in the report), skipped (lead, history, searched, out of scope). Model- and OCR-read rows stay
  `unconfirmed` until the quote matches on a re-fetched page (R-68, R-72).
- Load goes through `RegistryStore.record`, `ProgrammeStore.upsert` + `link_programme`, `SqlKnowledge.upsert` +
  `set_status(..., cause="review")`; every revision carries `cause_ref = import-<id>`; undo replays them backwards.
- CLI `scripts/os_import_batch.py` (template, validate, import, undo, list) and admin API `/admin/imports`.
- T3 (`PageGateway.fetch(..., scope)`, `SourceDomains.is_listed`) and T5 (`ReviewQueue.attested`, `open_item`) are used
  through narrow protocols (`sheets/ports.py`); tests use fakes.

## Spec clarifications (decisions made where the spec or README v4 left room; for the owner to see)
- **One check is `confirmed`, never `verified`.** Check 1 `correct` with check 2 unclear, missing or not an accepted check
  gives `confirmed` (also for rows that are not high-stakes). `verified` always needs both checks (P2-D6).
- **`conflict` stays `unconfirmed`** with a conflict item, even if both checks accepted the row (spec mapping over the
  README line).
- **Check 1 `not_readable` is `unconfirmed`** (README v4); Claude status `not_readable` queues a `collect` item (R-72).
- **Model- and OCR-read rows** need the quote match on a re-fetched page. The owner's ruling (spec §11.3) waives it only
  in the owner-accepted mode, for rows both AI checks accepted, in the five v4 files (listed by sha256 in
  `format.yaml`) and with a decision reference; the waiver is written to each fact's provenance. A missing
  `read_method` (older Programmes layouts) is treated the same way, never as `fetch`.
- **Foreign-country rows are skipped**, with their facts and programmes (`out_of_scope_regions` in `format.yaml`).
- **A programme row with no value column is rejected** (`no_value`); facts attach only to programmes that were loaded
  or already exist (`programme_not_loaded`).
- **Real imports need their ports**: rows that need a review item are refused when no review queue is connected, and
  with no allow-list connected no row goes above `unconfirmed`. A failed import stays live (the same file is not
  imported again) until it is undone; undo handles failed imports and every revision kind.
- **Intake mapping** (`intake_patterns` in `format.yaml`; approved by the owner, spec §11.3): `Fall 2027` -> fall 2027;
  `Session 2026-27` and `2026-27` -> session 2026; `Batch 2026` / `Annual 2026` -> batch / annual 2026; `2026` -> year
  2026 with no term. Anything else (`standing`, `current`, `previous cycle ...`) is queued as `intake_unresolved`.
- **The actor** of an API import is the identity behind the admin token (`admin`); a name typed in the form is kept as
  `note_actor`.
- **Undo and edits outside the revisions (known gap).** Undo checks for later changes through the revisions. A change
  that wrote no revision (a direct edit of a programme's columns, or of a registry row, outside `RegistryStore` and the
  stores' write paths) is not seen, and the restore overwrites it with what the import's first revision recorded as
  `before`. All normal write paths write revisions, so this only concerns hand edits. For links, the restore sets a
  system's links back to the first `link` revision's `before["links"]` of the import; if an import removed a link, undo
  refuses instead of putting it back.
