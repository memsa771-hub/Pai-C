  - the frozen contracts in `app/os/contracts/` (hash tests `tests/os/contracts/test_frozen*.py`).

  The replay tools may **import and patch** frozen modules, as `eval_counselor_deep.py` already does, but never edit them. `python scripts/check_freeze.py --base origin/pai-connect` must pass. If any task finds that a frozen file would have to change, **stop and report**. Do not plan around it.
- **No country, institution, exam or qualification names in `app/os` Python** (R-58, `tests/os/test_invariants.py:73`). Rule codes, finding codes and table names are generic. Route data stays in the YAML and the tests.
- **Ownership (master §4, R-01).** The consistency job **reads** both sides and **writes only its own case rows**. It never repairs data, never changes a plan, task, decision, outbox row or Vault item, and never stores a Vault value. Only the kernel changes plans (invariant 1, `test_invariants.py:34`). A case row holds codes, versions, IDs and hashes only.

- **Flags off means today, byte for byte.**
  - The job does nothing unless the OS is mounted, the `counsellor` module is on and `CONNECT_HANDOFF` is on.
  - Each rule runs only while its part is on: rules 5 and 7 need `CONNECT_STUDENT_FACTS`; rule 6 needs `CONNECT_ONE_UPLOAD`; rule 4 needs `CONNECT_ROADMAP_FROM_PLANVIEW`; rules 1, 2, 3 and 8 need `CONNECT_HANDOFF`.

  - Existing responses gain no field. New data travels only in new endpoints.
- **DB changes only by Alembic.** OS tree: `os_0024_consistency_cases.py`, `down_revision = "os_0023_student_requests"` (re-check after T8 merges). Counsellor tree: no migration. One head each (`backend/scripts/check_alembic_heads.py`).
- **Clock.** OS code uses `app.os.clock.now()` (`test_invariants.py:107`). Counsellor code uses `datetime.now(timezone.utc)`.
- **Logs** carry rule numbers, counts, IDs and class names, never values (no marks, names, emails or file names).
- **No live model call** without the owner's approval and a cost cap. Every replay in T10 is offline unless Task C3 is approved. `env -u PAI_API_KEY` on every Counsellor command; `OS_MODEL_MODE=offline` for the OS.

  - Adding the end-of-test check or a `standalone` mark to an existing test only adds assertions or CI coverage. No existing assertion is removed or loosened.

## 2. Decisions taken in this plan (controller; flagged to the owner in the PR)

- **D-z1, the shape of the job.** It has three parts:
  - **OS side:** a read-only port `app/os/ports/consistency.py` returns a per-student `OsSide` view: codes, versions, IDs and hashes only.
  - **Counsellor side:** `app/pai_c/connect/consistency.py` builds `CounsellorSide` and holds the **pure** rule function `check(c, o, *, mode, now) -> list[Finding]`.
  - **Glue:** `pai_os_bridge.consistency_run(db, *, mode, open_cases)` pairs the two views per student and runs the rules.

  The pure rules sit on the Counsellor side because `app/os` may not import Counsellor code (Tach), and the comparison needs both sides. The OS view is a frozen dataclass in the port, not a new contract (see Q11).
- **D-z2, two modes.**
  - `nightly` treats as **in flight**, and not a mismatch, anything younger than `2 × SWEEP_SECONDS` (10 minutes): a pending outbox row, a pending intake row, an unprocessed `student_fact_changed` event, or a waiting choice request.
  - `settled` (the end-of-test check) tolerates **nothing** pending. Its caller has just run one sweep and the OS intake. So "zero findings in `settled` after one sweep" is R-04's "within one sweep".
- **D-z3, how each rule reads.** A ✓ means not a mismatch. `c` is the Counsellor side and `o` the OS side.
  1. **Rule 1.** Take the newest decision with `status = chosen` and `os_supported = true`. ✓ when either:
     - the OS holds that version (`o.latest_version == v`) with an intake status in {`planned`, `revised`, `replaced`, `refused`, `held`, `paused`} and an open plan at version `v` (or a refusal reason recorded); or
     - `c` holds the outbox row as `not_sent` with a code. That is a recorded refusal on the Counsellor side; codes from `outbox.py:19-28`.

     Codes: `no_plan`, `version_behind`, `version_ahead`.
  2. **Rule 2.** For every open OS plan with `source = counsellor`: ✓ when `c` has an active decision for that student, and the plan's `contract_sha256` equals the hash of the route contract the OS derives from the Counsellor's **current** export of the applied version. The OS computes it with the intake's own mapping, `_contract_of` (`intake.py:186`). The intake row's `export_sha256` must also equal `plan_source.export_sha256(export)` (`plan_source.py:22`). Codes: `plan_without_decision`, `contract_hash`, `export_hash`.
  3. **Rule 3.** The newest decision is `withdrawn` → ✓ when every Counsellor-source plan of the student has `status = closed` with the withdrawn reason. Code: `plan_not_stopped`.
  4. **Rule 4.** ✓ when:
     - no row with `os_supported = true` has a non-empty `steps_done` written after its `chosen_at`;
     - no OS plan is open for a student whose newest decision has `os_supported = false`;
     - the roadmap serves OS steps (`kind = os`) for a supported route with an applied plan. This is read through `plan_adapter`, not by re-rendering the screen.

     Codes: `checklist_ticked`, `plan_for_unsupported`, `checklist_served`.
  5. **Rule 5.** ✓ when either:
     - `o.latest_vault_version >= c.vault_version`, and no `student_fact_changed` event for that student is still unprocessed (in `settled` mode); or
     - in `nightly` mode, a `vault_event` outbox row for the newest version is pending and in flight.

     Codes: `vault_behind`, `replan_pending`.
  6. **Rule 6.** Take every OS document of the student with a `file_ref` that an open plan's need or step uses. ✓ when that file is in the Counsellor `files` table for the same workspace and is not trashed. Codes: `file_missing`, `file_trashed`.
  7. **Rule 7.** ✓ when `duplicates()` (`requests/store.py:174`) lists nothing for the student. Code: `duplicate_request`.
  8. **Rule 8.** Take the excluded field keys (`excluded_fields`). ✓ when none of them is any of these:
     - the active decision's `field_key`, or the field of any of its places;
     - in the stage H list the Counsellor serves;
     - in the current path list (the C5 single reader).

     Codes: `in_choice`, `in_places`, `in_stage_h`, `in_paths`. The OS programme list has no field tag in P1 (T4 D-n), so the OS side of rule 8 is P2 (Q4).
- **D-z4, one case per student and rule.**
  - A nightly mismatch opens one row in `os_consistency_cases`, unique while open per `(tenant_id, student_ref, rule)` (Q1).
  - A later run that sees the same mismatch only updates `last_seen_at` and `codes`. A run that no longer sees it leaves the case open for a person to resolve. There is no auto-close: a person resolves it.
  - The end-of-test check never writes cases. It returns the findings.
- **D-z5, schedule (Q2).**
  - `start_consistency()` runs in the API process beside `start_sweep()` (`app/main.py:160-168`, only while `OS_MOUNTED`).
  - It sleeps until the next `CONNECT_CONSISTENCY_HOUR_UTC` (a new setting in `app/config.py`; default `21`).
  - It runs once per date: a run row `os_consistency_runs` with a unique `run_date` lets only one replica win.
  - The owner CLI `backend/scripts/connect_consistency.py run|status` runs it on demand. It prints counts per rule and never a student reference.
- **D-z6, row index.**
  - A new pytest marker `connect_row(*ids)` in `backend/pytest.ini`.
  - A meta test fails when any P1 row of master §6 (6.1–6.9, 6.11–6.19, 6.21, 6.22) has no marked test, and when a mark names a row that P1 does not test (6.10, 6.20, 6.23–6.25).
  - `scripts/check_traceability.py` is not changed. Rows are not R-IDs.
- **D-z7, stage A–I replay method (Q7).**
  - For each stage A–I, **seed** the workspace state of that stage with the existing fixture builders, then run 1–2 recorded Counsellor turns.
  - Capture every model call's **input** messages and the reply, action, decision and guard fields. A recorder wraps `RecordedModels`; it does not edit `eval_counselor_deep.py`'s behaviour.
  - Run it twice: off (module off, every `CONNECT_*` off) and on (module on, every `CONNECT_*` on, real OS on Postgres).
  - Normalise: mask IDs, timestamps and **fact values** (the `value` of Vault entries and of document-read facts). For screens, compare JSON **shape**: keys and types, not values.
  - Any other difference is a failure to report.

  A single conversation walking A→I with hand-written model outputs would be brittle, and stage I is screens anyway (master §10).
