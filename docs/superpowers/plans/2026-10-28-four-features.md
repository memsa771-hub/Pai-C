# Four Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Bring Vault, Mirror, Path engine and Roadmap engine to the map's target state (digital twin with a completeness meter; visual Mirror with no confirm gate; Vault-driven paths with semantic recall; per-step colour and time estimate), remove the old Mirror machinery, and clear the beta-blocking audit items.

**Architecture:** Everything derives from the Vault. New deterministic engines (`VaultCompleteness`, `MirrorEngine`, roadmap `route_steps` + `estimate`) are computed on read like the roadmap engine. One background model job writes the Mirror text. The reconciler is the single trigger point: after an accepted write it enqueues path analysis, the Mirror text and journey stage moves. Gates key on a Vault version digest instead of a Mirror version.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic (head 119), pytest; Next.js, vitest; Qdrant + OpenAI embeddings (optional at runtime).

**Spec:** `docs/counselor/FOUR_FEATURES_SPEC.md` (binding). Beta polish list: `.superpowers/sdd/2026-10-28-four-features/beta-polish-from-audit.md`. Current-state map: `.superpowers/sdd/2026-10-28-four-features/current-state-map.md`. Calendar research: `academic_calendar_draft.json` + `academic_calendar_summary.md` in the same folder.

## Global Constraints
- Branch `four-features` (from `roadmap-engine`). Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- No field, group, exam, area, copy or date hardcoded in code: data in `pai_c/policy/*.json`, `understanding/areas.json`, the Vault catalog, `copy.json`.
- No model call in any engine computed on read; the only new model job is `counselor.mirror_text`. No live API calls in tests (recall and embed are mocked). Never edit `.env`; never print secrets.
- DB changes only via Alembic (Task 1 = 120, Task 3 = 121). Dropping `pai_counselor_mirror_feedback` is in Task 3 (founder informed in the spec).
- Prompts in `.md`; sync `docs/counselor/COUNSELOR_V3_PROMPTS.md` for any prompt change (a test compares them).
- Evidence rule: nothing shown about the student without a Vault entry behind it; values render through catalog labels, never raw codes.
- Tests from `backend/` with the shim (`.superpowers/sdd/2026-10-28-four-features/env-notes.md`); frontend `npm test`, `npm run build`. Follow the workspace UI kit (`components/pai`, `Heading`, `useResource`, `StatChip`, `toneClass`).

## Review Focus
- Student with onboarding only (no chat): completeness 2/10, Mirror not ready, no paths, no 500 anywhere → Task 1 `test_completeness_onboarding_only`, Task 2 `test_mirror_not_ready_shows_known_areas`.
- Recall disabled or embedding key missing: every job and page returns the same shapes with no citations from recall → Task 1 `test_recall_off_is_empty_not_error`, Task 4 `test_analyzer_runs_without_recall`.
- Marks known but no Part-2 record: `marks` step done on Part-1 percent while `complete_intermediate` is half → Task 5 `test_marks_done_intermediate_half`.
- Today's date after the intake month: time estimate rolls to next year's intake, never negative → Task 5 `test_estimate_rolls_to_next_year`.
- Old journeys in RESEARCHING/ASSESSING/NEEDS_INFO or with a confirmed old Mirror: migration 120 moves them and the new Mirror page loads → Task 3 `test_migration_121_moves_waiting_journeys`, `test_legacy_mirror_draft_ignored`.
