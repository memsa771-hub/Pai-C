# P2-T2 registry: plan (R-32, R-33, R-34)

Spec: P2 spec §4.1, P2-D2/D3/D4/D8, §6.1 row T2. Builds on T1 (`os_0025`, `Fact`, regions, fact classes).
Migration `os_0026_registry` (down_revision `os_0025`; the controller renumbers at merge).

## Design (decisions made here)
- `os_registry`: one row per entity. `entity_id` is stable text `<prefix>:<slug>` (prefix per kind); kinds are the ten of
  §4.1 (code); instances are data. Columns: kind, parent_id, region (R-76 code), institution_type (free slug, from the
  official list), name, aliases, official_domains, status (`active/closed/merged/renamed`, successor_id), `list_ids`
  (the official lists it came from), source_url, quote, checked_at, `attrs` JSONB (kind-specific; for a list: body,
  date, row_count, count_quote, count_method, read_method, status, count_confirmed).
- `os_registry_revisions`: append-only history of registry rows (same causes as fact revisions; FK RESTRICT).
- `os_registry_links`: `uses_test`, `has_category`, `admits` edges from an admission system (the system's body is its
  `parent_id`). `admits` points at an institution/campus or at a programme ref.
- `os_programmes` gains nullable `institution_id, campus_id, level, field, family, region`.
- `ck_os_knowledge_facts_scope` widened with `registry` (facts about registry entities: cycle-bound, always per intake).
- `RegistryStore.record(entry, cause=..)` = `knowledge.record()` for registry rows: validates (kind/id prefix, region in
  vocabulary, https source + quote + tz-aware checked_at, institution/campus must name existing official lists, parent
  and successor must exist), upserts, writes one revision. No delete method.
- Coverage (R-34) is computed, never stored: `listed` / `researched` (any fact for the intake on the institution, its
  campuses, its programmes, the systems that admit it or its programmes and their tests/categories) / `verified` (>=1
  high-stakes fact and all high-stakes facts `verified`). `not_readable` flag in attrs keeps it `listed`.
- Official list progress: published count (as published; null if the page conflicts) against institutions naming it.
- `parse_official_lists(data, country)` reads the H3 research YAML shape (`docs/research/lists/*.yaml` on
  `pc/p2-research-batches`) into list entries; tests use fictional lists only.
- Admin read API: `GET /admin/registry/entities`, `/entities/{id}`, `/lists`, `/coverage`.
