## 4. Deviations and reasons

- **R-15 moved to P2 (owner ruling Q4).** Every Counsellor reader of an excluded field is done in P1 (C1/C5 in P0, the stage H list, rule 8 of the consistency check). The OS side is not: the OS programme list has no field tag in P1 (T4 D-n), and an exclusion of the chosen field raises no proposal. When the chosen field is excluded the nightly job opens a case (code `in_choice`), so it is never silent. R-15 stays `built: false`; P2 gives programmes field tags (`programme_list.v2`).
- **R-46 stays `built: false` until the live graded run is recorded** (item 7 of the gate). The offline proofs are done and tagged.
- **Stage I screens gain keys with the connection on (intended, R-44).** The stage A to I replay shows no difference in any Counsellor reply or model input for stages A to H. At stage I the screens carry new keys only with the connection on: `choose_response.choice`, `choose_response.plan`, `decision_record.plan`, `decision_record.steps[].{due_at, due_tz, estimated, owner, provisional, title}`, `roadmap.chosen.choice`, `roadmap.chosen.plan`, `roadmap.chosen.steps[].{due_at, due_tz, estimated, owner, provisional, title}`. With the connection off the responses are byte-for-byte today's.
- **The Germany CGPA gap (T8, decision needed).** Germany v2 asks only for the SSC and HSSC certificates; no source supports a transcript or CGPA ask. On a real Germany plan a CGPA conflict never becomes a "which is right" step. Row 6.21 is proven on a Germany v3 that exists only in the test. Adding a CGPA need to Germany needs an official source and the owner's approval of the wording.
- **Row 6.20 (result expected) is a mechanism only.** It runs in the T8 flow with a test calendar; the row is not counted as a P1 row (phase spec §1).
- **Row 6.18 "stage K" is interpreted (Q6):** the Counsellor has no stage K; a finished plan raises one `plan_finished` event and notice, the roadmap shows "finished", the check-in follow-up ends, and no journey stage is added (R-45).
- **An intermediate `plan_summary` returns None** (`app/os/summary.py`, D-u).
- **The consistency job's limits.**
  - Rules 9 to 13 of master §9.3 (they need Knowledge, allow-lists and `verified`) join the job in P2.
  - Rule 8 covers the Counsellor readers only (see R-15).
  - The gate run is one scenario per student, not one module-wide run, because in tests each student's Counsellor side is its own SQLite session while the OS side is one database. Production has one of each.
  - Rule 1 treats a finished (`done`) plan as holding its decision version, found while adding the end-of-test check to the 6.18 flow.
  - Flows that run with the part or module off on purpose (flags-off, module-off, gate-off tests) do not call the check: the job does not run there.
- **The replay's limits.** It uses recorded model outputs, so it cannot show how a real model answers the same input; it replays one or two turns per stage on seeded state, not one conversation from A to I; it forces each analysis job to succeed; the new endpoints (choice options, places, My plan) exist only with the connection on and are covered by their own tests.
- **Follow-ups from T8 PR #200 "For the owner":**
  - Known limits: a student whose Vault holds a finished bachelor record cannot choose places (409, older than T8); a Vault card that opens after a plan exists reaches the OS only on the hourly recompile.
  - Behaviour choices: a ladder proposal stays open if the student answers afterwards (this follows the plan); when a contract revision changes `student_ref`, old open rows keep the old student (rare); two rules (`_rejected`, `fact_all_below`) still count removed places.
  - Ruling problems awaiting the owner's confirmation: 1, 2, 4, 5, 6, 7, 8 and 9 (listed with their rulings in the T8 plan).
